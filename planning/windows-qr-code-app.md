# Windows向けQRコード生成アプリ 企画検討メモ

作成日: 2026-09-03
状態: 検討中（決定事項は末尾「決めたこと・決めていないこと」に集約）
関連: [5人会議の議事録](./windows-qr-code-app-meeting.md) — 本メモのMVP案を5つの立場で叩き、
合意した要件一覧を確定した。本メモと食い違う場合は議事録を優先する。

## 0. 先に結論

- **勝ち筋は「データをPCの外に出さない、印刷して失敗しないQR生成」**。Webの生成サイトは
  無数にあるが、業務で使いにくい理由がはっきりしている（③参照）。そこを正面から取る。
- **主戦場は一括生成**。単体生成は「入口」であって差別化にならない。Excel/CSVを
  読み込んで数百〜数万件を命名規則付きで書き出す機能が、業務ユーザーが金を払う理由になる。
- **MVPは「静的QRのみ・完全オフライン・Excel一括・読み取り検証つき」**。動的QR、
  ロゴ埋め込み、ラベル面付け印刷は後回しでよい（④⑤参照）。
  会議の結果、**1枚印刷と連続入力モード**はMVPに繰り上げた（議事録参照）。
- **収益は買い切りPro＋端末数ライセンスのBusiness**。サブスクは動的QR（サーバー費用が
  かかるもの）に限定する（⑥参照）。
- 名称に注意。「QRコード」はデンソーウェーブの登録商標であり、製品名に含める場合は
  同社の商標利用ガイドラインを確認する必要がある。本メモでは仮称として **「QRファクトリー」**
  ではなく、商標を含まない仮称 **「CodePress」** を使う（最終名称は未定）。

## 議論の進め方

4つの立場を置いて、各項目で意見を出し、対立点を明示した。

| 立場 | 関心事 | 口癖 |
|---|---|---|
| PM | 誰に、何を、いつ出すか。優先順位 | 「それはMVPに要るか」 |
| 設計者 | 実装コスト、保守性、Windowsの制約 | 「その要件は技術的に何を意味するか」 |
| 営業 | 売れるか、稟議が通るか、競合に負けないか | 「情シスが首を縦に振るか」 |
| 利用者 | 今日の仕事が終わるか。迷わないか | 「で、どのボタンを押せばいい」 |

### 4視点のコメント

- **PM**: 34種類を全部相手にはできない。初期のコア顧客は **#1〜#3（製造・物流・総務）と
  #6（多店舗マーケ）**。理由は「件数が多い」「Webに貼れない情報」「毎月繰り返す」の3つが
  揃う。個人は無料枠で広く取り、口コミと検索流入を担わせる。
- **営業**: #3総務は狙い目。資産管理タグは全社で必ず発生し、担当者はExcelの台帳を
  持っている。「その台帳からそのまま作れます」で話が終わる。
- **設計者**: #10医療は入力に患者IDが入る。アプリ側は文字列を扱うだけだが、
  ログや履歴に残す設計にすると医療情報を保持する製品になる。履歴保存は既定オフ、または
  入力値を保存しないモードが要る。
- **利用者（総務）**: 「うちのExcelは1行目が見出しじゃない。3行目から始まる」。
  一括の入力は、見出し行の位置指定と列の手動選択が要る。

## ② 利用シーン（具体例）

### シーン1: 資産管理タグを一括で作る（#3 総務）

新年度で200台のノートPCが入った。資産番号 `PC-2026-0001` から連番。台帳のExcelがある。

1. Excelをドラッグして読み込む。3行目が見出しなので「見出し行=3」を指定
2. 「資産番号」列をQRの内容に、「資産番号」列をファイル名に指定
3. サイズを 20mm×20mm、300dpi、余白4セル、誤り訂正 M に設定
4. QRの下に資産番号を印字するオプションをオン（読めないときに人が読める）
5. 200枚のPNGがフォルダに出る。ラベルプリンタのソフトに渡す

**痛点**: Webサービスだと1件ずつ。Excelで一括できるサービスは有料でアカウント登録が要り、
資産番号とホスト名をアップロードすることになる。情シスが止める。

### シーン2: 店舗別の計測URL付きPOP（#6 多店舗マーケ）

全国120店舗のキャンペーンPOP。URLは `https://example.com/cp?store=012` のように店舗ごとに変える。
デザイナーがIllustratorで差し込む。

1. 店舗マスタのCSVを読み込む
2. 「QRの内容」を **テンプレート式** で組み立てる: `https://example.com/cp?store={店舗コード}`
3. 出力を **SVG** にする（印刷解像度に依存しない）
4. ファイル名を `{店舗コード}_{店舗名}.svg` にする
5. 120個のSVGをデザイナーに渡す

**痛点**: 既存ツールはCSVの1列をそのまま内容にするものが多く、URLの組み立ては
Excel側で列を作る必要がある。テンプレート式があれば一段減る。

### シーン3: 来客用Wi-Fiの掲示（#4 情シス、#27 家庭）

会議室に「Wi-Fi接続QR」を貼る。

1. 種類で「Wi-Fi」を選ぶ
2. SSID、暗号方式（WPA2/WPA3）、パスワードを入力
3. 「隠しSSID」チェック
4. 印刷用のA4レイアウト（QR＋SSID＋説明文）で印刷

**痛点**: WebにWi-Fiパスワードを入力するのは、それ自体が社内規程違反になる会社がある。
家庭でも「このサイト信用していい？」という不安がある。

### シーン4: イベント受付（#7 イベント運営）

申込者3,000人にメールで受付QRを送る。当日、スマホで読み取って受付。

1. 申込リストのExcelを読み込む（申込ID、氏名、メール）
2. 内容は申込ID（もしくは署名付きトークン列を別途用意）
3. ファイル名を `{申込ID}.png` にして3,000枚出力
4. メール配信ツールの差し込み画像として使う

**痛点**: 3,000件を1件ずつは無理。Webの一括は件数課金。さらに氏名とメールを
外部サービスにアップロードする合意を取る必要がある。

**設計者の補足**: 受付側（読み取り）はスコープ外。ただし「このQRが本物か」は
受付側の課題で、アプリは HMAC 付きトークン列を生成する補助機能を将来持てる（⑩）。

### シーン5: 設備点検札（#1 製造、#22 保守）

工場の設備500台に点検札を貼る。読み取ると点検フォーム（Microsoft FormsやKintone）が
開き、設備IDが入力済みになる。

- 内容: `https://forms.example/xxx?equip={設備ID}`
- 屋外・油汚れ環境なので **誤り訂正 H**、サイズ 30mm 以上
- 札は3年使う。**動的QRサービスに依存させない**（サービス終了で全札が死ぬ）

### シーン6: 授業プリント（#8 教員）

毎週のプリントに解説動画のQRを載せる。Wordに貼る。

1. URLを貼り付ける
2. プレビューが出る
3. 「コピー」ボタンでクリップボードへ
4. Wordに Ctrl+V

**利用者の声**: 「保存先を聞かれるのが面倒。コピーして貼りたいだけ」。
単体生成の体験は **入力→即プレビュー→コピー** で完結すべき。

### シーン7: 段ボールの中身管理（#28 個人）

引っ越しで50箱。箱ごとに中身をテキストでQRにして貼る。ネット不要。読めば中身が出る。

- 内容: `箱12: 冬服、毛布、加湿器`（URLではない自由テキスト）
- **日本語がスマホで文字化けしない** ことが必須（UTF-8、ECI）

### シーン8: 名刺のvCard（#16 営業、#23 個人事業主）

- 氏名、会社、電話、メール、URL からvCard 3.0 を生成
- 日本語の姓名とふりがな（`X-PHONETIC-*`）を入れる
- **注意**: vCardはデータ量が多く、QRが密になる。名刺サイズで読めるかの警告が要る

### シーン9: 校正ラベル（#18 品質保証）

- 内容: 計測器ID＋校正日＋次回校正日を JSON か区切り文字で
- ISO 監査で「いつ誰が発行したか」を問われる → **発行ログ** が要る（⑧）

### シーン10: 印刷会社の差し込み（#15）

- 10万件。1件ずつファイルではなく、**1つのPDFに面付け**、または Illustratorのデータ結合用に
  連番ファイル
- **中断・再開** と **失敗行の一覧** がないと実務にならない

## ③ なぜ既存の手段では不十分か

| 既存手段 | 何が困るか | 誰が特に困るか |
|---|---|---|
| Webの無料生成サイト | 広告。1件ずつ。入力内容がサーバーに送られる。「無料」と見せて動的QR（短縮URL経由）にされ、後で有料化や失効で読めなくなる例がある | 業務全般、Wi-Fi・個人情報を扱う人 |
| Webの有料一括サービス | アカウント登録、件数課金、月額。顧客リストをアップロードする合意が要る。プロキシで止まる | 総務・情シス・イベント |
| 動的QRのサブスク | 印刷した後にサービスが終了・解約すると全部死ぬ。3年貼る札には使えない | 製造・保守・教育 |
| ExcelのVBA・バーコードフォント | 64bit Officeで動かないActiveX、作った人が退職して保守不能、Shift_JISで漢字が化ける | 総務・製造 |
| ラベルプリンタ付属ソフト（P-touch Editor等） | そのプリンタ専用。PNG/SVGで他へ渡せない。Illustratorに入れられない | マーケ・印刷 |
| Illustrator/InDesignのデータ結合 | 高価。オペレーターが要る。QRのプラグインが別売り | 印刷以外の全員 |
| Pythonスクリプト（qrcode, segno） | 非エンジニアには無理。社内PCにPythonを入れられない | 総務・教員 |
| 古いWindowsフリーソフト | 更新停止。高DPIで滲む。SVG非対応。ロゴ不可。漢字がShift_JIS固定で今のスマホで化ける | 全員 |
| スマホアプリ | PC上のExcelと連携できない。大量出力に向かない。印刷が面倒 | 業務全般 |

### 共通する3つの痛点

1. **データが外に出る**（規程・心理的抵抗・情シス承認）
2. **一括ができない、できても高い・遅い・列の対応づけが硬い**
3. **印刷してから読めないと分かる**（余白不足、小さすぎ、色反転、ロゴで潰れた、漢字が化けた）

3つ目は既存ツールがほぼ手当てしていない。生成した画像をアプリ自身がデコードして
「読めます／余白が足りません／このサイズだと約30cm以内でないと読めません」と示すだけで
体験が変わる。

### 4視点の対立

- **営業**: 「Webで十分と言われたらどう返すか」→「Wi-Fiのパスワードをそのサイトに
  入れましたか」で返せる。データ非送信は営業トークとして最強。
- **PM**: ただし個人ユーザーはWebで満足している人が多い。個人向けは「無料で広告なし、
  登録不要」以上の訴求は要らない。
- **設計者**: 「データを送らない」は **ネットワーク機能を一切持たない** ことで証明できる。
  更新確認すら既定オフにするか、手動にする。これは動的QR（⑤v2）と矛盾するので、
  動的QRは別モジュールまたは別製品に切る判断が要る。

## ④ MVP（最初の公開版）

判断基準: **「Excelを持った総務担当者が、ダウンロードから30分以内に200枚のタグを
作って印刷できる」**。これを満たさない機能は外す。

### 入っているもの

**単体生成**
- 入力種別: テキスト／URL、Wi-Fi、連絡先（vCard 3.0）、メール（mailto）、電話（tel）、SMS
  - 内部的には全部「文字列を組み立てるフォーム」。種別追加は安い
- 入力した瞬間にプレビュー更新
- 誤り訂正レベル L/M/Q/H（既定 M、説明文つき）
- サイズ指定: ピクセル、または **mm＋dpi**（印刷用）
- 余白（クワイエットゾーン）: セル数で指定（既定4、減らすと警告）
- 前景色・背景色（コントラスト不足を警告。反転は警告して許可）
- 出力: PNG、SVG。クリップボードへコピー。名前を付けて保存。ドラッグして他アプリへ
- **1枚印刷**: mm指定でプリンタへ。標準のプリンタ選択ダイアログのみ（会議で繰り上げ）
- **連続入力モード**: 入力欄でEnter→確定→次の入力待ち。ハンディリーダーからの連続入力向け（会議で繰り上げ）
- 用途プリセット（屋内ラベル／屋外・油汚れ／名刺／画面表示）でサイズ・誤り訂正・余白をまとめて決める
- 文字コード: UTF-8（ECI付き／なし）、Shift_JIS。既定はUTF-8
- 情報表示: バージョン（21×21〜177×177）、バイト数、残り容量
- **読み取り検証**: 生成画像を自前でデコードして内容一致を表示

**一括生成**
- 入力: CSV（文字コード自動判定＋手動）、Excel（.xlsx、シート選択、見出し行指定）
- 列の対応づけ: 「内容」「ファイル名」「キャプション（任意）」を列から選ぶ
- **テンプレート式**: `https://example.com/?id={ID}` のように列名を差し込める
- 出力先フォルダ、ファイル名の重複時の動作（連番付与／上書き／スキップ）
- プレビュー: 最初の数件を並べて見せる。容量超過や空セルは実行前に一覧表示
- 実行: 進捗、キャンセル、失敗行のCSV書き出し
- 生成設定は単体と共通（サイズ・誤り訂正・色・余白・文字コード）
- 設定をプロファイルとして保存・読み込み（JSON）

**配布・動作**
- Windows 10 (22H2) / 11、x64（Arm64は後で）
- インストーラ（MSI）とZIP解凍で動くポータブル版の両方
- 管理者権限なしで入る（per-user）
- コード署名
- **ネットワーク通信なし**。更新確認も手動。これを設定画面の1行目に書く
- 日本語・英語UI
- 高DPI対応（滲まない）

### 入っていないもの（意図して外す）

| 外すもの | 理由 |
|---|---|
| 動的QR、計測 | サーバーが要る。オフライン訴求と矛盾。v2で別建て |
| ロゴ埋め込み、ドット形状の装飾 | 読めなくなる原因の筆頭。検証機能が固まってから（v1.1） |
| ラベル用紙への面付け印刷 | 実装が重い。1枚印刷で「剥がれた1枚の貼り直し」は足りる。面付けはv1.1 |
| 履歴の自動保存 | 医療・個人情報の観点で既定オフ。v1.1で「保存しない設定つき」で追加 |
| QR以外のコード | ⑩へ |
| CLI | 業務の自動化で欲しいが、MVPのコア顧客（総務）はGUIで足りる（v1.1） |
| Microsoft Store配布 | 審査と署名の準備に時間がかかる。直接配布で先に出す |

### 4視点の議論

- **利用者（総務）**: 「一括の画面で、どの列がQRになるかを表で見せてほしい。
  実行してから間違いに気づくのが一番つらい」→ プレビューと事前チェックはMVPから外さない。
- **設計者**: Excel読み込みは ClosedXML などの純マネージド実装で、Excel本体を不要にする。
  Excelが入っていないPC（現場端末）でも動く。
- **PM**: 種別のフォーム（Wi-Fi、vCard）は各1画面。まとめて出しても工数は小さいので入れる。
  ただしvCardは項目数が多い。MVPは氏名・ふりがな・会社・部署・電話・メール・URLの7項目に絞る。
- **営業**: MSIとポータブル版の両方は必須。「ZIPを解凍して置くだけ」で試してもらい、
  正式導入でMSIをSCCM/Intuneで配る流れが定番。

### 技術選定（設計者の提案）

| 選択肢 | 評価 |
|---|---|
| .NET 8 + WPF | 成熟。印刷・高DPI・MSI・署名の情報が豊富。単一exe配布可。**推奨** |
| .NET + WinUI 3 | 見た目は今風だが、ランタイム配布とポータブル運用が面倒 |
| Electron | 200MB超。オフライン訴求と「軽い」を両立しにくい |
| Tauri | WebView2 依存。企業の古い環境で WebView2 が無い・止められている例がある |

QRライブラリは MIT ライセンスの純.NET実装（例: QRCoder、ZXing.Net）。デコード検証には
ZXing.Net を使う。**ライセンスは配布時に表示**する。

- **利用者（マーケ）**: 動的QRは欲しいが、他社サービスで痛い目を見た。
  「自社ドメインでリダイレクト」なら安心して使う。

## ⑥ 有料化できるポイント

### 料金プラン案

| プラン | 対象 | 価格の目安 | 含むもの |
|---|---|---|---|
| Free | 個人、試用 | 無料 | 単体生成は全機能・無制限。一括は **1回50件まで**。PNG/SVG。透かしなし。広告なし |
| Pro | 個人事業主、部門の担当者 | **買い切り 4,000〜6,000円**（メジャーバージョン内の更新込み） | 一括無制限、面付け印刷・PDF、ロゴ、テンプレート、CLI、連番 |
| Business | 企業（複数端末） | **端末数×年額**（例: 10台 30,000円/年〜）または買い切り＋保守 | Pro全機能＋サイレントインストール、ポリシー配布、監査ログ、優先サポート、見積・請求書払い |
| Dynamic（オプション） | マーケ | 月額（リダイレクト件数・スキャン数で段階） | 動的QR、計測、自社サーバーでのリダイレクト |
| SDK / CLI ライセンス | 印刷会社、SIer | 年額 | 自社システムに組み込み。再配布 |

### 設計上の要点

- **透かしを入れない**。透かし入りQRは読み取りに影響する上、印象が悪い。制限は件数で行う。
- Freeの一括50件は「試せるが、本番では足りない」ライン。イベントや資産管理は必ず超える。
- **買い切りを主軸**にする。理由: 業務ユーザーは稟議で「年額」より「一括購入」が通りやすい。
  個人も月額に強い拒否感がある。ランニングコストが発生しない静的QRで月額を取る理由がない。
- サブスクは **サーバー費用が発生する動的QRだけ**。ここは明確に「サービス」として売る。
- ライセンスキーはオフラインで検証できる形式（署名付きキー）。**アクティベーションにネット必須は
  避ける**。オフライン訴求と矛盾するため。
- Businessは「台数を数えない」誘惑があるが、ボリュームライセンスは **申告制＋監査条項** で十分。
  厳密なDRMは情シスに嫌われる。

### 4視点の議論

- **営業**: 法人は「見積書・注文書・請求書払い」ができるかで決まる。決済サイトだけだと
  クレジットカードを持たない部門が買えない。販売代理店（ベクター、法人向けソフト販売店）経由も検討。
- **PM**: 最初の売上はProで小さく立つ。Businessは導入事例が2〜3件出てから本格化。
- **設計者**: ライセンス検証は単純に。複雑にすると問い合わせが増えて損。
- **利用者（個人）**: 「月額なら使わない。5,000円なら1回払って終わりにしたい」。

## ⑦ 競合との差別化

### 差別化の柱（優先順）

1. **「PCから出ない」を製品の中心に置く**
   - ネットワーク機能ゼロ。設定画面と製品ページの最初に書く
   - セキュリティチェックシート（情シス提出用）を用意して配る
2. **「印刷して失敗しない」**
   - 生成時にデコード検証
   - 物理サイズから読み取り可能距離の目安を表示（例: 20mmなら約20〜40cm）
   - 余白・コントラスト・密度の警告
   - 「ロゴを入れたら読めなくなった」を起きる前に止める
3. **Excelで完結する一括**
   - 見出し行指定、列の対応づけ、テンプレート式、事前チェック、失敗行の書き出し
4. **日本の実務向け**
   - Shift_JIS/UTF-8の選択と、古いリーダー向けの案内
   - 国内ラベル用紙プリセット
   - vCardのふりがな
   - 見積書・請求書払い
5. **静的で壊れない**
   - 「10年後も読める」。動的QRサービス依存の怖さを教育コンテンツ（記事）で伝える
6. **買い切り**

### 競合分類と対抗

| 競合の型 | 例 | 対抗 |
|---|---|---|
| Web無料生成 | 多数 | データ非送信、広告なし、一括 |
| Web有料一括・動的 | 海外SaaS | 買い切り、オフライン、日本語実務 |
| ラベルソフト | プリンタ付属 | 汎用出力（PNG/SVG/PDF）、プリンタ非依存 |
| 旧来のWindowsフリーソフト | 更新停止のもの | 現代的なUI、高DPI、SVG、検証機能、継続更新 |
| Office内製（VBA） | 社内 | 保守不要、64bit問題なし、担当者交代に耐える |

### 営業のフック案

- 「**Wi-Fiのパスワード、あのサイトに入れましたか**」
- 「**貼ってから読めないと分かる前に**」
- 「**台帳のExcelから、そのまま200枚**」

## ⑧ 業務利用ならではの要件

### 導入・配布

- MSIインストーラ、サイレントインストール（`/quiet`）、SCCM・Intune配布の手順書
- per-user インストール（管理者権限不要）と per-machine の両方
- ポータブル版（実行ファイル＋設定ファイルのみ。レジストリを触らない）
- コード署名（EV証明書が望ましい。SmartScreen警告を出さない）
- **セキュリティチェックシート**（通信の有無、保存する情報、暗号化、ログ）を配布
- 更新は自動で行わない。管理者が配る。更新通知は既定オフ
- 前バージョンとの並存（検証用）

### 環境

- Windows 10 22H2 / 11。Windows 10 は延長サポート下の企業がまだいるので当面は対応
- プロキシ、インターネット遮断環境で完全動作
- 共有PC（現場端末）で複数ユーザーが使う。設定は per-user、テンプレートは共有フォルダ
- 高DPI、複数モニタ、リモートデスクトップ
- 日本語IME、全角入力の正規化オプション（全角英数→半角）

### データと再現性

- **同じ入力・同じ設定→同じ出力**。ライブラリのバージョンを固定し、変えるときは告知
- 設定プロファイル（JSON）で担当者交代に耐える
- 入力ファイルを変更しない（読み取り専用で開く）
- 履歴は既定オフ、または「内容を保存しない」モード
- 監査ログ（v2）: 日時、ユーザー名、プロファイル名、件数、出力先。**内容は記録しない**選択肢

### 一括の規模と信頼性

- 10万件で止まらない。メモリを行ごとに解放
- 中断・再開（出力済みをスキップ）
- 失敗行の一覧（行番号、理由）をCSVに書き出す
- 空セル、重複、容量超過、不正文字の事前検出
- ファイル名に使えない文字（`/ \ : * ? " < > |`）の自動置換ルール
- 出力先のサブフォルダ分け（1,000件ごと、列の値ごと）

### 印刷と物理要件

- mm単位＋dpi指定。300/600dpi
- 帳票の所定位置に貼る用途で **誤差1mm以内**
- 誤り訂正の既定は M。屋外・汚れる用途は H を案内
- 反転（白黒逆）はリーダーによって読めないので警告
- 最小セルサイズの目安（一般に 0.33mm 以上）を表示

### 規格・法規

- JIS X 0510 / ISO/IEC 18004 準拠
- GS1 用途（食品、医療）はv2で。AI の組み立てを間違えると業界で読めない
- **決済用QR（JPQR等）は本アプリの対象外**と明記。決済事業者の発行物を使うよう案内
- 医療機関での患者IDは、施設側のガイドラインに従う旨を案内
- 「QRコード」商標の表記（デンソーウェーブのガイドライン）

### サポート・商流

- 問い合わせ窓口（メール）。返信目安を明示
- 見積書、注文書、請求書払い、複数年
- ライセンス証書（PDF）
- 導入時の「よくあるトラブル」FAQ（読めない原因の一覧）

### 4視点の議論

- **営業**: 導入で止まる理由の上位は「通信の有無が説明できない」「署名がなくてSmartScreenが出た」
  「MSIがない」。機能ではなく配布形態で負ける。
- **設計者**: 「通信なし」を証明するため、ビルドにネットワーク関連のアセンブリを含めない。
  第三者の検証を受けやすくする。
- **利用者（製造）**: 「現場PCはExcelが入っていない」→ Excel本体に依存しない読み込みは必須。
- **PM**: 監査ログとポリシー配布はBusinessの差別化。MVPには入れないが、
  設定ファイルの構造だけは最初から「上書き可能な階層」にしておく。

## ⑨ 個人利用ならではの要件

### 体験

- ダウンロードして **登録なし・設定なし** で即使える
- 起動1秒以内。軽い（数十MB以内が目標）
- **入力→即プレビュー→コピー** の3手で終わる
- 保存先を聞かない選択肢（クリップボードコピー、デスクトップにドラッグ）
- スマホで画面を直接読ませる用途があるので、**画面上で大きく表示するモード**（全画面）
- ヘルプを読まなくても分かる。用語は「誤り訂正」ではなく「汚れに強い」など言い換えの併記

### 見た目

- 色、角丸、ロゴ（v1.1）。年賀状や名刺に載せたい
- 一方で **かわいくしたら読めない** を防ぐ。装飾しても検証が通ることを見せる
- ダーク/ライトテーマ

### 安心

- 広告なし、無料枠が実用的（単体は無制限）
- 通信しない。個人にも刺さる（「怪しいサイト」に入れたくない）
- Microsoft Store 配布（v1.1以降）。「Storeにある」だけで安心する層がいる
- アンインストールでゴミを残さない

### 個人ならではの機能

- Wi-Fi、連絡先、段ボールの中身（自由テキスト）
- 連番なしの簡単一括（「このURL 30個、家族の名前入りで」→ 連番生成の簡易版）
- 年賀状・名刺サイズのプリセット（mm）
- 日本語の自由テキストが化けない（UTF-8既定）

### 4視点の議論

- **利用者（教員）**: 「Wordに貼れればいい。SVGとか知らない」→ 既定はPNG。SVGは「詳細」に隠す。
- **PM**: 個人向けの機能追加は無料枠の魅力＝口コミの源泉。ただし個人からの要望に
  引きずられてUIを複雑にしない。「簡単モード／詳細モード」の切り替えで守る。
- **設計者**: 簡単モードは「詳細の既定値を隠すだけ」で実装する。2つのUIを作らない。
- **営業**: 個人利用者は法人の担当者でもある。家で使って会社に持ち込む導線が実際に多い。

## ⑩ 将来的にQR以外へ拡張できる方向性

### A. コードの種類を広げる（近い）

| 種類 | 用途 | 需要元 |
|---|---|---|
| JAN/EAN-13、UPC | 商品バーコード | 小売、食品、同人（ISBN/JAN） |
| Code128、Code39 | 資産・ロット・伝票 | 製造、物流、総務 |
| ITF-14 | 段ボール外装 | 物流 |
| NW-7（Codabar） | 図書館、血液バッグ | 図書館、医療 |
| Data Matrix | 小部品の直接刻印 | 製造、医療 |
| PDF417 | 運転免許・搭乗券系 | 公共 |
| rMQR、Micro QR | 細長い面積、小面積 | 製造 |
| GS1 QR / DataMatrix | 食品・医療のトレーサビリティ | 食品、医療 |

ライブラリは同じ系統で済み、UIは「種類の選択」が増えるだけ。ただし1次元コードは
**チェックデジットの自動計算**と**印刷幅の規格**が要るため、種類ごとに検証ロジックが必要。

### B. 読み取り側へ（近い）

- 画像・PDF・スクリーンショットからのデコード
- 印刷物を撮った写真で「読めるか」を判定する検品モード
- 一括デコード（フォルダ内の画像を全部読んで CSV に）
  - 印刷会社の **出荷前検品**、イベントの **回収済みチケットの集計** に使える

### C. 差し込み印刷・ラベル設計ツールへ（中）

- QRを含む名札・ラベル・名刺のレイアウト編集
- 「差し込み印刷でQRを載せたい」需要は QR 単体より大きい
- Word の差し込み印刷が苦手な人（多い）を取れる
- ここまで来ると製品カテゴリが「ラベル作成ソフト」になり、競合が変わる

### D. 業務台帳へ（中〜遠）

- 資産管理タグを作ったら、その台帳も持ちたくなる
- 「QRを起点にした簡易台帳」（設備・備品・蔵書）
- ただし台帳は競合が多く、深入りすると本業を失う。**連携（CSV出入力、Kintone等）に留める**判断もある

### E. 認証・改ざん防止へ（遠）

- 署名付きQR（公開鍵で検証）。チケット、証明書、入退室
- 検証アプリ（スマホ）が必要になり、製品が2つになる

### F. NFC・他媒体へ（遠）

- 同じ内容をNFCタグに書き込む（Wi-Fi、URL、vCard は NDEF で表現できる）
- Windows PC に NFC ライタが付いている例は少ないので優先度低

### G. ブランドとしての拡張

- 「Windowsの業務小物ツール」シリーズ化。和暦変換など既存の小物と並べる
- 共通の配布基盤（MSI、署名、ライセンス、ポリシー配布）を再利用できる
- 個々の製品は小さくても、「情シスが許可しやすい小物ツールの作者」という信用が資産になる

### 4視点の議論

- **PM**: 順番は A → B → C。A はほぼコストなしで対象顧客が倍になる（物流・小売）。
  B は差別化の柱「印刷して失敗しない」を強くする。C は別製品として切る。
- **営業**: 物流・小売は「JANも一緒に作れる」で商談が広がる。1次元対応は早めに欲しい。
- **設計者**: 最初から「コードの種類」を抽象化しておく。QR固有の設定（誤り訂正）と
  共通設定（サイズ、余白、色）を分けて設計する。
- **利用者（印刷）**: 読み取り検品が一番欲しい。作る側より「納品前に全部読めるか」が怖い。

## リスクと落とし穴

| リスク | 対応 |
|---|---|
| 「QRコード」商標の扱い | 製品名に含めない。表記は「QRコードはデンソーウェーブの登録商標です」を添える |
| 装飾で読めなくなる | 生成後デコード検証を必須にし、失敗時は保存できないのではなく **警告して選ばせる** |
| Shift_JIS と UTF-8 の混乱 | 既定UTF-8。Shift_JISは「古いリーダー向け」と注記。両方を試せるプレビュー |
| 大量出力でのメモリ・時間 | ストリーミング処理。進捗とキャンセル。10万件でベンチマーク |
| SmartScreen で怪しまれる | コード署名。初期は評判が育つまで時間がかかる前提で、ポータブル版と併用 |
| 動的QRで製品の性格が変わる | 別モジュール／別exe。静的版は通信コードを含めない |
| 個人情報を扱う製品と見なされる | 履歴既定オフ。監査ログに内容を残さない。チェックシートで明記 |
| 決済QRを作ろうとする利用者 | 対象外を明記。誤用を防ぐ |
| 「無料の一括50件」で足りてしまう | 50件は市場を見て調整。ただしケチると口コミが死ぬ |

## 決めたこと・決めていないこと

### 決めたこと（本メモの提案として）

- コア顧客は総務・製造・物流・多店舗マーケ。個人は無料枠で口コミを担う
- MVPは静的QRのみ、完全オフライン、Excel/CSV一括、読み取り検証つき、1枚印刷、連続入力モード
- 履歴は「設定の保持」と「内容の履歴」を分け、内容は既定オフ・ポリシーで禁止可
- 設定はポリシー＞ユーザー＞既定の階層。固定項目は見えるが変更不可
- 収益は買い切りPro＋Business。サブスクは動的QRのみ
- 技術は .NET + WPF、純マネージドのExcel読み込み、MIT系のQRライブラリ
- 製品名に「QRコード」を含めない

### 決めていないこと（次に決める）

1. 製品名と、商標表記の最終確認
2. Free の一括上限（50件案）と Pro の価格（4,000〜6,000円案）
3. Microsoft Store 配布をいつやるか（v1.1案）
4. 動的QRを「別exe」にするか「同梱の別モジュール」にするか
5. 販売経路（自社サイトのみ／ベクター等の代理店／法人向け販売店）
6. Windows 10 のサポート終了時期
