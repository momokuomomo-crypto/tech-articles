答えは日付によります。1月7日までが昭和64年、1月8日からが平成元年です。

手元の変換ツールに `1989` と入れてみてください。おそらく「平成元年」とだけ返ってきます。**1月1日から7日までの7日間について、それは誤りです。**

この境界を教えるChrome拡張を作りました。

[Chromeウェブストアで入手する](https://chromewebstore.google.com/detail/pcgbpaagcljfakbhmoiaoekmfbfdfpob)

## 何をするか

改元のあった年は、境界日を必ず注記で示します。

```
入力：1989/1/8

  平成元年1月8日
  1989年1月8日
  ※ 1989年は1月7日までが昭和64年、1月8日からが平成元年
```

年だけを入れた場合も、両方を並べます。

```
入力：1989

  昭和64年（1月1日〜1月7日）
  平成元年（1月8日〜12月31日）
```

## 存在しない和暦を作らない

`昭和64年1月8日` は存在しません。昭和は1月7日で終わっているためです。

多くのツールは、これを黙って平成元年1月8日として扱います。**Javaの標準ライブラリですら、デフォルト設定では例外を出さずに書き換えます。**

この拡張は書き換えません。期間外であることを示したうえで、正解を併記します。

```
入力：昭和64年1月8日

  昭和64年は1989年1月7日で終わっています
  この日付は 平成元年1月8日 です
```

**黙って直すのと、誤りを指摘したうえで正解を出すのは別のこと**だと考えています。書類の日付を直すとき、どちらが必要かははっきりしています。

## そのまま貼れる

日付は整った形で手に入るとは限りません。次はすべて受け付けます。

```
1989/1/8        19890108        1989年1月8日
平成元年1月8日   H1.1.8          H1年1月8日
H元/1/8         西暦1989年1月8日  １９８９年１月８日（全角）
生年月日：1989年1月8日            1989年1月8日（日）
```

`生年月日：` のような先頭ラベルと、`（日）` のような曜日が付いていても、そのまま貼れます。申請書や既存データからコピーした文字列を、整形せずに投げられます。

使い方は2通りです。

- ツールバーのアイコンから開くポップアップに入力する
- **ページ上の日付を選択して右クリック**する

## 入れる前に確認したいこと

**権限は3つだけです。**

```
contextMenus, storage, notifications
```

ページの内容を読み取る権限（`host_permissions`・`activeTab`・`scripting`）は要求しません。**閲覧しているページを、この拡張は見られません。**

**外部への通信を一切行いません。** 入力した日付も設定も、この端末から出ません。ソースコードに通信の処理が1つもないことは、[リポジトリ](https://github.com/momokuomomo-crypto/chrome-ext-wareki-converter)で確認できます。

アカウント登録も課金もありません。

## 対応範囲

正確を期すため、できないことも書いておきます。

- **1873年1月1日（明治6年1月1日）以降**のみ対応します。明治5年以前は旧暦のため、元号年から西暦への機械換算が成立しません
- 同梱の元号データには確認期限があります。それを超える日付も変換しますが、**その後に改元があった場合は正しい和暦が異なる旨の注記**が付きます
- 右クリックの結果はChromeの通知に表示します。OS側で通知が抑制されている場合（Windowsの集中モードなど）は表示されません。その場合はポップアップに結果が残ります

## 誰のためか

- 申請書・履歴書・各種書類で和暦と西暦を行き来する人
- 行政・人事・学校の事務で、生年月日を扱う人
- 業務システムで和暦を実装している開発者

最後の用途は、和暦変換で踏む6つの罠をJDKで確かめたに詳しく書きました。境界日の扱いがどれだけ厄介かをまとめてあります。
